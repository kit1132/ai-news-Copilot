### 1. Purview DLP が Cowork へ広がる — Cowork のプロンプトを内容で止められるようになる

**要点**: **570845** が起票され、M365 Copilot と Cowork を **1本の DLP ポリシー**で統制できるようになる。Cowork の統制点がテナント一括のトグルしか無かった前提が変わり、プロンプトの中身とナレッジソースの粒度で止められる。

**詳細**: Roadmap 項目「Microsoft Purview: Data Loss Prevention for Microsoft Cowork」は Preview が **2026年9月**、GA が **2026年10月**である。データセキュリティ管理者は既存の DLP ポリシーをそのまま Cowork へ効かせられる、というのが起票文の骨子で、効き方は3つに分かれる。

- ラベル付きナレッジソースを Cowork に使わせない
- 対応する機微情報の種類（sensitive information types）を含むプロンプトをブロックする
- 機微なプロンプトが Bing の Web 検索へ送られるのを制限する

これまで Cowork 側で管理者が握れていたのは、M365 管理センターの Cowork settings（ブラウザー利用の可否、Anthropic モデルファミリーのテナント一括オフ）と、利用者の既存アクセス権限の継承だけだった。⚠️ **3つ目は B-044 で追ってきた Web 検索統制と重なる**——現行の `Allow web search in Copilot` ポリシーは Copilot / Copilot Chat / Work モードの3択しか持たず、Cowork には利用者向けトグルすら無い。DLP 側から機微プロンプトだけを止める経路が加わることで、統制の粒度が「面ごと」から「内容ごと」へ移る。⚠️ **一方 `purview/whats-new` は `updated_at` 2026-08-28T07:31Z のままで、本項目も 570445（自動ラベル付けの拡張）も掲載されていない**（**B-016 回数 42**・**B-042 回数 19**）。
